## Dependencies

| Id | Severity | Rule | What it checks | Remediation | Reference |
|---|---|---|---|---|---|
| TCA-DEP-001 | Critical | Cyclic toolkit dependency | Toolkits depend on each other in a cycle (A needs B, B needs A). Process Center accepts it in some versions but installs, upgrades and snapshot migrations become fragile and the toolkits cannot be versioned independently. | Break the cycle: move the shared artifacts into a lower-level common toolkit both can depend on, or merge the two toolkits. |  |
| TCA-DEP-002 | Critical | Recursive service call cycle | Services call each other in a cycle (directly or through other services). | TCA-DEP-003 | Major | Unused service | A service of the application is not referenced by any process, service, coach, UCA, web service or exposure. | TCA-DEP-004 | Minor | Unused business object | A business object is not referenced by any variable, parameter, property, coach view binding or service. | Delete obsolete business objects to keep the data model understandable. |  |
| TCA-DEP-005 | Minor | Unused coach view | A coach view is not used by any coach, human service or other coach view. | Delete the coach view or move it to a UI toolkit if it is meant for reuse. |  |

## Service

| Id | Severity | Rule | What it checks | Remediation | Reference |
|---|---|---|---|---|---|
| TCA-SVC-001 | Major | Step not connected to the flow | A step of the service has no incoming link (and is not the start step) or no outgoing link (and is not an end/exit). It is either dead code or a flow that stops without reaching an end point. | Wire the step into the flow or delete it. Every path should end in an End/Exit point. | IDA check-service-step-incorrectly-referenced |
| TCA-SVC-002 | Critical | Service without start step | The service has steps but no start item is defined, so it cannot be executed. | Open the service diagram and connect the Start node to the first step. | IDA check-service-not-fully-implemented |
| TCA-SVC-003 | Major | Empty or unimplemented step | A script step has no code, or a service/sub-process call step points to nothing. The step does nothing at runtime, which usually hides an unfinished implementation. | Implement the step or remove it from the flow. | IDA check-service-item-not-implemented |
| TCA-SVC-004 | Critical | Call to a service that is not in the export | A step calls a service whose id is not found in the application or its toolkits (deleted or in a toolkit version that is not bundled). The service fails at runtime. | Re-attach the step to an existing service; verify the toolkit dependency versions. |  |
| TCA-SVC-005 | Major | Loop without exit in the service flow | The links form a cycle whose steps have no link leaving the cycle (no condition can break it). The service will loop forever or until the transaction times out. | Add a decision (Switch) with an exit condition, a loop counter with a maximum, or restructure the flow. | IDA check-service-item-contains-infinite-loop |
| TCA-SVC-006 | Major | No error handling in a service that calls other services | The service calls sub-services / integrations but neither the service nor the calling steps have an error handler. An exception surfaces as a failed task or instance with a generic message. | Attach an error (catch) event to the integration/call steps or enable the service-level error handler, log the error and map it to a business-friendly outcome. | IDA check-bpd-component-need-exception-handle |
| TCA-SVC-007 | Critical | Error handler loops back into the failing step | The error path of a step leads back to the same step (retry without a counter), which repeats the failure endlessly. | Add a retry counter and a maximum, or route the error to an end state / notification. | IDA check-service-exception-loop-item |
| TCA-SVC-008 | Major | Too many input or output variables | The service has more than 15 input or output parameters. Long parameter lists make the service hard to call and to change; they usually indicate missing business objects. | Group related parameters into a business object. | IDA check-service-with-too-many-inputvariables |
| TCA-SVC-009 | Major | Unused variable | A private variable or parameter of the service is never referenced in any script, mapping or coach binding of the service. | Remove the variable; unused variables confuse maintainers and still cost serialisation. | IDA check-service-unused-variables |
| TCA-SVC-010 | Major | Script on the exit point | Code attached to an End/Exit point runs after the outputs are already mapped; it is easy to miss when reading the flow and cannot be error-handled. | Move the logic into a script step before the exit. | IDA check-service-event-end-contains-script |
| TCA-SVC-011 | Major | Too many coaches in one human service | A human service with more than 5 coaches is hard to follow and to test; it usually contains several tasks in one service. | Split the human service by task or use nested client-side human services / coach views for reusable screens. | IDA check-humanservice-with-too-many-coach |
| TCA-SVC-012 | Major | Stay-on-page directly after a postpone | A Stay On Page event follows a Postpone step; the postponed task is immediately resumed, which defeats the postpone. | Route the postpone to an end state, or remove the stay-on-page event. | IDA check-service-SOPE-directly-follow-postpone-object |
| TCA-SVC-013 | Critical | Decision (Switch) without a default path | A switch step has only conditional outgoing links. | TCA-SVC-014 | Minor | Step logging / tracing enabled | A step has execution logging or tracing switched on. In production this writes every execution to the logs / trace tables and slows the service down. | Disable logging and tracing on the step before releasing (use it only while debugging). |  |
